# figma-mcp

جسر محلي بين **Claude Code** و **Figma Desktop**. سيرفر MCP مع بلجن فيجما وسكيلز بتحدد طريقة الشغل.
كلود بيقرا الفايل ويفهمه، وبيصمم جواه بأوتو لاي أوت وفاريبلز وستايلات وكمبوننتس بفاريانتس، وبيربط البروتوتايب،
وبيسحب التصميم لكود زي `get_design_context` بتاع فيجما الرسمي. كل ده من غير API token ولا خطة مدفوعة ولا ليميت.

```
Claude Code ⇄ (MCP · stdio) ⇄ figma-mcp server ⇄ (WebSocket · localhost:7457) ⇄ بلجن "Figma MCP" ⇄ ملف التصميم
```

## فيه إيه

- **24 أداة MCP** بتغطي القراية والكتابة والتحويل لكود (الجدول تحت).
- **تنظيم ثابت لكل فايل**: الصفحات بأسامي إنجليزي، وكل صفحة بتتعمل أول ما حاجة تتحط عليها بس، ومفيش صفحة فاضية بتفضل.
  - `App` (أو صفحة لكل أب: `App – Customer` و `App – Driver`)، و `Web`، و `Dashboard`، و `Banners`.
  - `Components`: كل الكمبوننتس والأيقونات هنا. `create_component` بيحطها هنا، و `to-component` بيشيل الكمبوننت لهنا ويسيب instance مكانه.
  - `References`: الريفرنسات بتتحط هنا كبورد بحروف (A, B, C…) جوه سكشن `References – <لأي جزء>`، وانت تختار حرف.
  - `Trash`: أي حاجة بتتمسح بتروح هنا، وتقدر ترجّعها بـ `restore` لمكانها.
- **مفيش تكرار**: كل شاشة فريم واحد. لو فيه شاشة بنفس الاسم على الصفحة، `build` بيرفض ويقول: عدّل الموجودة أو استبدلها بـ `replaceId` (القديمة بتروح Trash).
- **مقاسات مظبوطة**: `device` بيدّي الفريم المقاس بالظبط، زي `iphone-16` 393×852، و `android` 412×917، و `desktop` 1440×1024، و `instagram-story` 1080×1920، ومقاسات الإعلانات.
- **الصور**: أي صورة التصميم محتاجها بتبقى placeholder عليه رقم (`IMG-001`) و prompt.
  - `image_prompts` بيكتب كل الـ prompts في `IMAGE_PROMPTS.md` جوه مشروعك، بالمقاس والنسبة واسم الملف.
  - تعمل الصور وتحطها في فولدر `images` جنبه، و `place_images` بيحط كل صورة مكانها في فيجما.
  - نفس الـ prompt في أكتر من مكان بياخد نفس الرقم، فصورة واحدة بتملا كل الأماكن.
  - أو صور stock مجانية: `stock_photos` بيدوّر في Unsplash و Pexels لو حاطط مفتاح (`UNSPLASH_ACCESS_KEY` / `PEXELS_API_KEY`، أو `~/.figma-mcp/keys.json`)، ومن غير مفتاح كلود بيدوّر بنفسه ويحط لينك الصورة.
  - صور مواقع التصميم (Dribbble، Behance، Pinterest…) ريفرنس بس: الأدوات بترفض تحطها في التصميم برا صفحة `References`.
- **الريفرنسات**: `references` بياخد لينكات (Awwwards، One Page Love، مواقع حقيقية، Dribbble/Behance) أو سكرين شوتس، بينزّل صور الشغل في فولدر `references` في مشروعك ويعمل البورد.
  - المواقع اللي بتمنع التحميل الآلي (غالبًا Dribbble و Behance) أو اللي محتاجة لوجين (Mobbin) بيقول عليها بوضوح، وتبعتلها سكرين شوت.
  - بعد ما تختار حرف، كلود **مش بيشرح الريفرنس**: بيبنيه قريب منه على الصفحة الحقيقية بالهوية بتاعتك (ألوانك، خطوطك، كمبوننتسك، أيقوناتك، محتواك)، وبعدين انت تطلب التعديلات.
- **`build` بمواصفات JSON**: شاشة كاملة في نداء واحد.
  - فريمات أوتو لاي أوت، والمقاسات fill/hug/fixed، و grid.
  - فاريبلز `"$color/bg"` وستايلات `"@Heading/H1"`.
  - إنستانسز بفاريانتس وبروبرتيز.
  - أيقونات من Iconify بتتحفظ كمبوننتس، وصور من ملف أو لينك، وبروتوتايب inline، ودعم RTL للعربي.
  - بيتأكد من كل اسم (فاريبل، ستايل، كمبوننت، خط) **قبل** ما يلمس الفايل، ويقترح التصحيح.
  - لو فيجما وقعت في النص، بيشيل الجزء اللي اتعمل، فالفايل ميتبهدلش.
- **كمبوننتس بفاريانتس**: base spec ومحاور (Size × State …) و patches. الأداة بتطلّع الـ set كامل:
  - بروبرتيز (text / boolean / instance swap) مربوطة بالليرز.
  - حالات تفاعلية (hover/press) مربوطة.
  - الفاريانتس مترتبة في جريد.
- **فاريبلز وستايلات بالجملة**: كولكشنز ومودز (Light/Dark…) و aliases. الـ scopes وكود `var(--…)` بيتحطوا تلقائي.
- **بروتوتايب**:
  - لينكات بتريجرز وترانزيشنز مكتوبة كلام عادي، زي `"smart-animate 300ms ease-out"`.
  - overlays، و flows، و scroll مع عناصر ثابتة.
  - تبديل مود (Dark) جوه البروتوتايب.
- **سحب التصميم لكود** (`get_design_context`):
  - كود مرجعي React + Tailwind أو HTML + CSS.
  - التوكنز كـ CSS variables بقيمها في كل مود.
  - الكمبوننتس، والأصول (بتتصدّر لفولدر المشروع)، والانتراكشنز، وسكرين شوت.
  - `componentMap` يربط كمبوننت فيجما بكمبوننت الكود عندك.
- **`export_tokens`**: الفاريبلز كـ CSS أو Tailwind v4 (@theme) أو SCSS أو DTCG JSON.
- **`lint`**: مراجعة بالمبادئ.
  - بيفحص الكونتراست، والنص المضغوط أو المقصوص، وأي لون أو مسافة أو ريدياس مش مربوطة بتوكن، والنص اللي من غير ستايل، والفريمات اللي محتاجة أوتو لاي أوت، والكمبوننتس المفصولة، وأحجام اللمس، والأسماء العشوائية.
  - مع `fix: true` بيربط القيم اللي ليها توكن واحد مطابق بالظبط.
- **`execute`**: كود Plugin API كامل لأي حاجة مش متغطية، ومعاه مساعدات `h`.
- **brief جوه الفايل نفسه**: فهم كلود للمنتج والقرارات بيتحفظ في ملف فيجما، فكل جلسة بتكمل من مكان اللي قبلها.
- **أكتر من فايل وأكتر من جلسة**:
  - أول جلسة كلود بتشغّل الـ hub، والباقيين بيتوصلوا بيه.
  - لو الجلسة اللي شغالاه قفلت، جلسة تانية بتستلم تلقائي.
  - كل جلسة بتفضل ماسكة الفايل اللي اشتغلت عليه.
- **زرار Pause** في لوحة البلجن بيوقف أي تعديل من كلود فورًا.

## السكيل: مدخل واحد بيوجّه نفسه

فيه سكيل واحد بس اسمه **figma-mcp**. في Claude Code بتناديه `/figma-mcp:figma`، وفي باقي الأدوات `@figma-mcp` أو `$figma-mcp`. ومش لازم تناديه أصلًا: أي طلب فيه فيجما أو تصميم بيحمّله لوحده.

- **الموجّه (router):** أول السكيل جدول بيحدد نوع الطلب، وكلود (أو Codex أو غيره) بيقرا الدليل المناسب لوحده قبل ما يبدأ:

  | الطلب عن… | الدليل |
  |---|---|
  | شاشات، فلوهات، لاندنج، داشبورد، بانرات، أو تصميم من ريفرنس | `design.md` |
  | هوية واحدة لكل حاجة: تثبيت البراند، استخراجه من موقع أو سكرينشوتس، توحيد التصميم ومراجعته، ونقله للكود (`DESIGN.md`) | `identity.md` |
  | فاريبلز، ستايلات، كمبوننتس وفاريانتس، ثيمات | `design-system.md` |
  | بروتوتايب وانتقالات و overlays | `prototype.md` |
  | تحويل التصميم لكود في المشروع | `to-code.md` |
  | صور محتاجة تتعمل | `image-prompts.md` |
  | تفاصيل `build`، والـ `execute`، والأخطاء | `build-spec.md` و `execute.md` و `troubleshooting.md` |

- **بتناديه مرة واحدة:** بعد كده أي طلب في نفس المحادثة بيروح للدليل الصح لوحده، حتى لو الطلب نوعه اتغيّر (من تصميم لكود مثلًا). عمره ما هيسألك تستخدم أنهي سكيل.
- **الأدلة بتحدد طريقة الشغل، مش شكل التصميم:** الستايل بييجي من البريف والبراند والفايل نفسه.

## التركيب: أمر واحد

من جوه الفولدر، أياً كان مكانه:

```bash
npm run setup
```

أو دبل كليك على **`setup.command`** في Finder.

- **بيجيب المسارات لوحده كل مرة:** مكان الفولدر و `node`. مفيش مسار مكتوب ثابت في أي حتة.
- **بتختار من ليستة:** بيعرض الأدوات اللي على جهازك (Claude Code و Codex و OpenCode و Antigravity و Cursor و Gemini CLI و Claude Desktop). جنب كل واحدة مكتوب لو كانت موجودة أو متسطّب عليها figma-mcp. الأسهم بتتحرك، و Space بيختار، و Enter بيسطّب.
- **لو نقلت الفولدر:** الأدوات بتشغّل لانشر ثابت في `~/.figma-mcp`، وده بيدوّر على الفولدر ويلاقيه لوحده. Claude Code بيقرا البلجن من الفولدر نفسه، فبعد النقل شغّل الأمر تاني وهو بيسجّله في مكانه الجديد.
- **فيجما (مرة واحدة):** بيقولك تعمل Import من `~/.figma-mcp/figma-plugin/manifest.json`، والمسار بيتنسخ لوحده. المكان ده مش بيتغيّر، فمش هتعمل Import تاني لو نقلت الفولدر. ولو فيه نسخة قديمة مستوردة من مكان تاني بيقولك تشيلها.

من غير ليستة: `npm run setup -- claude codex` أو `npm run setup -- --all`. عشان تشوف هيعمل إيه من غير ما يغيّر حاجة: `--dry-run`. وكل الاختيارات: `--help`.

> أول مرة بس، لو مفيش `node_modules`: `npm install`. دي أدوات البناء، أما السيرفر نفسه فملف واحد مبني.
> تفاصيل كل أداة في [CLIENTS.md](CLIENTS.md).

## الاستخدام اليومي

1. افتح ملف التصميم، وبعدين **Plugins → Development → Figma MCP**، وسيب اللوحة الصغيرة مفتوحة.
2. افتح جلسة Claude Code في أي مشروع واطلب على طول. أمثلة:
   - «اعمل لي شاشة تسجيل الدخول للتطبيق ده بنفس الديزاين سيستم»
   - «اعمل فاريبلز Light/Dark من البراند ده»
   - «اعمل كمبوننت Button بفاريانتس وحالات hover»
   - «اربط البروتوتايب لفلو الدفع»
   - «اسحب الشاشة دي وابنيها في المشروع» (مع لينك فيجما أو حدد الفريم)
3. اللوحة بتعرض كل أمر كلود بينفذه ومدته. **Pause** بيوقف التعديل.

## الفولدر ده بيفضل نضيف

- كلود بيشغّل البلجن من الفولدر ده مباشرة. عشان كده فيه **حارس (PreToolUse hook)**:
  - أي جلسة شغالة في مشروع تاني ممنوعة تعدّل أو تكتب أو تمسح أي حاجة هنا.
  - الأوامر المسموحة هنا هي القراية بس، زي `cat` و `ls` و `grep`.
- أداتا `export` و `export_tokens` وتصدير الأصول **بيرفضوا** يكتبوا هنا، وبيكتبوا في فولدر مشروعك.
- الملفات اللي بتتعمل أثناء الشغل مكانها **برّه** الفولدر ده:
  - اللوج وكاش الأيقونات في `~/.claude/plugins/data/…`.
  - البريف جوه ملف فيجما نفسه.
- عشان تطوّر الأداة نفسها: افتح Claude Code **جوه** الفولدر ده، أو شغّله بـ `FIGMA_MCP_UNLOCK=1`.

## استكشاف الأخطاء

```bash
npm run doctor     # البناء، والتسجيل، والبورتات، والفايلات المتوصلة، وآخر سطور اللوج
```

| المشكلة | الحل |
|---|---|
| «Not connected» | شغّل البلجن في فيجما ديسكتوب وسيب لوحته مفتوحة |
| اللوحة مكتوب فيها «Waiting for Claude Code…» | بتتوصل أول ما جلسة كلود تستخدم الأداة. لو شباك فيجما مستخبي ورا شبابيك تانية ممكن تاخد لحد دقيقة، والأدوات بتستناها. جيب فيجما قدام يسرّع |
| البلجن اتقفل لوحده | فيجما بتشغّل بلجن واحد بس في نفس الوقت. شغّله تاني |
| «plugin build differs» | البلجن بيتحدّث لوحده أول ما كلود يستخدمه. لو التحديث كان في واجهة اللوحة نفسها، اقفل البلجن وشغّله تاني |
| فيجما بتقول «Limited to 1 modes» أو ترفض Set Variable Mode | دي حدود خطة فيجما المجانية (Starter): مود واحد بس لكل كولكشن، ومفيش set-mode في البروتوتايب. الأداة بتقولك ده وبتكمّل الباقي |
| PAUSED | دوس Resume في اللوحة |
| «already exists on page» | فيه شاشة أو كمبوننت بنفس الاسم. كلود المفروض يعدّل الموجود بدل ما يعمل نسخة تانية |
| `place_images` محطّش صور | اسم كل صورة لازم يبدأ برقمها (`IMG-001…`) وتكون في فولدر `images` جنب `IMAGE_PROMPTS.md` |

## التطوير

```bash
npm run check      # typecheck + build + tests (unit + integration مع بلجن وهمي)
npm run build      # بعد أي تعديل
node scripts/e2e.mjs <out-dir>        # اختبار شامل على فيجما الحقيقية (البلجن لازم يكون شغال في ملف تجربة)
node scripts/call.mjs status '{}'     # نداء أداة واحدة من التيرمنال
```

بعد `npm run build`:
- الجلسات الجديدة بتشغّل السيرفر الجديد. في جلسة شغالة استخدم `/mcp` (reconnect) أو `/reload-plugins`.
- بلجن فيجما بيتحدّث لوحده (hot reload) أول ما كلود يكلّمه. تعديلات واجهة اللوحة بس هي اللي محتاجة تقفله وتفتحه.
- السكيلز بتتقري من هنا مباشرة، و`/reload-plugins` بيحمّلها.

| المسار | فيه إيه |
|---|---|
| `src/shared/` | البروتوكول، ومواصفات build، والألوان (مشتركين بين السيرفر والبلجن) |
| `src/plugin/` | كود بلجن فيجما (Plugin API) |
| `src/ui/` | لوحة البلجن (WebSocket) |
| `src/server/` | سيرفر MCP، والـ hub، وتوليد الكود، والتوكنز |
| `src/guard/` | حارس الفولدر |
| `claude-plugin/` | بلجن Claude Code: السكيلز، و hooks، و `.mcp.json`، و dist |
| `agent-skills/` | نسخة من السكيلز للأدوات التانية (Codex، OpenCode، Antigravity…). بتتولّد مع `npm run build`، متعدّلهاش بإيدك |
| `CLIENTS.md` | شرح التشغيل مع كل أداة |
| `setup.command`، `scripts/setup.mjs`، `scripts/clients.mjs` | أمر التركيب، وطريقة كل أداة في حفظ إعداداتها |
| `scripts/home-launch.mjs` | اللانشر اللي بيتنسخ لـ `~/.figma-mcp` ويلاقي الفولدر لو اتنقل |
| `figma-plugin/` | اللي بتعمله import في فيجما |
| `test/` | الاختبارات |

## الإزالة

```bash
claude plugin uninstall figma-mcp@figma-mcp-local
claude plugin marketplace remove figma-mcp-local
rm -rf ~/.figma-mcp ~/.agents/skills/figma-mcp*
```
- **الأدوات التانية:** امسح `figma-mcp` من ملف إعداداتها (`npm run doctor` بيقولك أنهي أدوات متسطّب عليها). وكل ملف اتعدّل ليه نسخة احتياطي جنبه باسم `.bak-figma-mcp`.
- **فيجما:** Plugins → Development → Manage plugins in development → Remove.
