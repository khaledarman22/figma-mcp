# Prototyping with principles

A prototype is a promise of how the product behaves. Make it complete (no dead ends), consistent
(the same gesture always means the same thing) and honest (it only shows what the product will do).

## 1. Map before wiring
- Prototypes live on the screens' own page (`App`, `Web`, …) — no separate prototype page or copies of screens for it. Never link to anything on `Trash` or `References`.
- `get_metadata` on the page: list screens and their states. `prototype` with `read: true` shows what is already wired.
- Write the flow: start screen → happy path → branches (errors, empty, cancel, back). Name it after the user's journey ("Checkout", "Onboarding").
- Missing screens/states for the flow? Design them first (figma-mcp-design).

## 2. Wire everything that looks interactive
- Every button, link, tab, list row, back arrow, close icon and nav item does something.
- Back arrows → `back`; close icons on overlays → `close`; tabs → `navigate` to the tab's screen (or `change-to` the tab variant inside a tab component).
- External links → `url`.
- Address layers by id, by ref, or by name path: `from: "Payment > Pay button"`, `to: "Payment success"` (top-level frame names).

## 3. Consistent motion
| Meaning | Transition |
|---|---|
| Forward in a stack | `push left 300ms ease-out` (RTL: `push right`) |
| Back | `back` action (Figma reverses automatically) |
| Modal / bottom sheet | `overlay` + `move-in bottom 300ms ease-out` |
| Dialog | `overlay` + `dissolve 200ms ease-out` |
| Same screen, changed state | `smart-animate 250ms ease-out` (layer names must match between the frames) |
| Tabs / instant switches | `instant` or `dissolve 150ms` |
Durations 150–400 ms; one easing family per product; springs (`gentle`, `quick`) for playful products.

## 4. Scrolling and fixed elements
- Long screens: `scroll: [{ id: "<screen>", overflow: "vertical", fixed: <n> }]` — `fixed` counts the top-most layers that stay (header, tab bar). In `build`, mark those children `"fixed": true` and set `"scroll": "vertical"` on the screen.
- Horizontal carousels: a frame with `scroll: "horizontal"` and `clip: true`.

## 5. Interactive components
States live in the component (figma-mcp-design-system): `create_component` with `interactions: [{ from: { State: "Default" }, trigger: "hover", to: { State: "Hover" } }, { from: { State: "Default" }, trigger: "press", to: { State: "Pressed" } }]`. Instances in screens then behave without extra wiring. Toggles/checkboxes: `click` → `change-to` the other value.

## 6. Variables in prototypes
- Theme switch: `{ from: "<toggle>", trigger: "click", action: "set-mode", collection: "Theme", mode: "Dark" }` (paid Figma plans only — the Starter plan rejects Set Variable Mode actions; then link to the screen's dark-state frame, `Screen – Dark`, instead).
- Simple state: `set-variable` (boolean/number/string/color).

## 7. Flows and review
- `flows: [{ name: "Checkout", start: "<first screen>" }]` — one starting point per journey.
- `prototype` read → review the list: every screen reachable, every screen has a way back, no orphan links.
- Overlay position/background can't be set through the API: tell the user if an overlay needs a non-default position (Prototype panel → Overlay).
- Tell the user how to try it: Present (▶) from the flow starting point.

## Example
```json
{
  "links": [
    { "from": "Cart > Checkout button", "trigger": "click", "action": "navigate", "to": "Checkout / Address", "transition": "push left 300ms ease-out" },
    { "from": "Checkout / Address > Back", "trigger": "click", "action": "back" },
    { "from": "Checkout / Address > Change", "trigger": "click", "action": "overlay", "to": "Address picker", "transition": "move-in bottom 300ms ease-out" },
    { "from": "Address picker > Close", "trigger": "click", "action": "close" },
    { "from": "Splash", "trigger": "after 1200ms", "action": "navigate", "to": "Home", "transition": "dissolve 300ms" }
  ],
  "flows": [{ "name": "Checkout", "start": "Cart" }]
}
```
`from` takes an id, a ref, a screen name, or a name path `"Screen > Layer > Sublayer"` (first match by layer name). `to` takes an id, a ref or a screen name.
